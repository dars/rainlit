# 狀態機輔助測試方法 v1

2026-09-22。模型 gpt-5.6-luna / gemini-3.5-flash。使用相同 19 步連續情境，14 次模型演出、5 次固定文案。各供應商 low 推理、輸出上限 1600，temperature 使用各自預設。程式見 ../run-state-dialogue.py；每輪完整提示、前後狀態、台詞、用量與總延遲見各模型 JSON。

這是測試用 Python reducer，尚未接網頁，也不是完整生產狀態機。動作標籤人工指定，沒有測自由文字分類可靠率。狀態僅在測試程序中前進，未實作交易、網路失敗替代、turnId 去重或跨裝置存檔。因此不能宣稱已驗證所有狀態機設計。

固定文案步驟：14 讀信、16 消化信、17 提出離開、18 出門、19 空位。其餘步驟由模型生成。固定步驟不計模型成功率或延遲平均；測試不將模型自然語言寫回 state，因此資料層安全不代表文字不矛盾。

本次同時改提示、提供權威狀態、縮短歷史至最近 12 則並改用連續情境，並非只改一個變因的因果實驗。與上一輪只能做定性觀察，不能聲稱狀態機使品質提高特定百分比。兩家之間使用同一測試條件，但各自之前的模型台詞會影響後續對話。

Reducer 基本斷言：無傘不能交付；未授權不能讀信；道歉後仍戒備；尊重界線後回到 neutral；完整路徑正確離場；離場後呼叫不改狀態。這些斷言通過不代表其他所有路徑都已覆蓋。
